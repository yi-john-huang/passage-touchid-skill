# Backup and independent recovery

Keep local Git **only** at `~/.passage/store`; before `git init`, confirm ownership and scope. Commit only `.age-recipients` and encrypted `*.age` entries. Never commit identities, plaintext, backup files, private SSH keys, AWS credentials, or temp files. No remote without explicit separate approval. Filenames and Git history reveal metadata even when entry contents are encrypted; audit tracked paths/history. Retain encrypted source keys/credential sources until separately approved deletion.

An off-device recovery backup needs **both** encrypted store Git history and `identities.backup.age`, with its recovery passphrase retained independently. Never copy the device-bound `~/.passage/identities` off-device: it does not transfer the Secure Enclave key. Protect backup file with mode `0600` and backup directories with mode `0700` where supported. Check restored ciphertext byte-for-byte against the source, `git fsck --full` on the copied store, and decrypt a copied dummy ciphertext using only the encrypted recovery identity and human passphrase before calling backup usable. Do not delete originals. After a restart, explicitly rerun a recovery check; never label a skipped post-restart check as passed.

For an approved ExFAT copy, `ditto` may introduce `._*` AppleDouble sidecars inside Git objects and make the copy invalid. Run `dot_clean -m <newly-created-backup-directory>` **only on that new copy** (never on originals); set `git -C <copied-store> config core.filemode false` only in its copied repository. Then compare ciphertext byte-for-byte and run `git -C <copied-store> fsck --full`. For the recovery test pipe decrypted backup identity directly into `age -d -i /dev/stdin <copied-dummy.age>` and compare output against a known dummy literal via `cmp`; no decrypted temp files. This check does not replace verifying the passphrase is stored independently and that the off-device backup can be retrieved.
