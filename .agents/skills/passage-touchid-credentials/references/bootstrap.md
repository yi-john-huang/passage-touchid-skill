# Bootstrap: personal macOS only

Before mutation, check `sw_vers -productVersion` (macOS 14+), Touch ID enrollment and Secure Enclave availability in System Settings, and `fdesetup status` (FileVault on). Check `command -v brew age age-plugin-se passage gnu-getopt tree python3`, `age --version`, `test -e "$HOME/.passage"`, and inspect paths/permissions **without opening unknown identities or entries**. If `~/.passage` already exists and its provenance is unknown, stop; do not overwrite or initialize it. Confirm credentials are personal, not company/work or ambiguous. Get user approval before installing software or migrating any real source.

Install dependencies with `brew install age age-plugin-se gnu-getopt tree` (and `brew install python` only if Python 3 is missing). Ensure Homebrew's `gnu-getopt` executable is on PATH as `getopt` for Passage insertion; use the path printed by `brew info gnu-getopt` for this machine. If Passage is absent, use the latest **tagged** release of [FiloSottile/passage](https://github.com/FiloSottile/passage/releases) only: download/verify its tagged source and follow its bundled [INSTALL](https://github.com/FiloSottile/passage/blob/master/INSTALL): from that release directory, `make install PREFIX="$(brew --cellar)/passage/$(git describe --tags)"` then `brew link passage`. Check the tag and installation files before executing them. Do not use untagged HEAD or `gpanders/passage`.

For a **new** store set `umask 077`, create `~/.passage` and `~/.passage/store` with mode `0700`; private identity/backup files mode `0600`. Generate the device-bound identity into `~/.passage/identities` via `age-plugin-se keygen --access-control=any-biometry-or-passcode --recipient-type tag -o "$HOME/.passage/identities"` when age >=1.3; derive its public recipient via `age-plugin-se recipients --recipient-type tag -i "$HOME/.passage/identities" >> "$HOME/.passage/store/.age-recipients"`. On older supported age, use `--recipient-type se` in **both** commands instead. Do not interchange tag and se derivation. Do not copy this device-bound identity off-device.

Generate an **independent** recovery identity encrypted with a human-entered passphrase, without ever writing its plaintext to disk: `age-keygen | age -p -o "$HOME/.passage/identities.backup.age"`. Confirm passphrase storage independent of the device. Derive only its public recipient by interactively decrypting into the next process: `age -d "$HOME/.passage/identities.backup.age" | age-keygen -y >> "$HOME/.passage/store/.age-recipients"`. Avoid terminal transcripts or debug tracing of these pipelines. Keep the encrypted backup mode `0600`; `.age-recipients` is public metadata. Check both recipient lines before proceeding. Passage encrypts entries to the nearest `.age-recipients`; do not add an overriding one containing only one recipient.

Use generated non-secret dummy text first: `printf 'setup-check\n' | passage insert -m misc/setup-check` (confirm insertion if prompted). Prove Touch ID decrypts: `passage show misc/setup-check | cmp - <(printf 'setup-check\n')`. Prove independent passphrase recovery, with the encrypted backup supplying the identity **through stdin**: `age -d "$HOME/.passage/identities.backup.age" | age -d -i /dev/stdin "$HOME/.passage/store/misc/setup-check.age" | cmp - <(printf 'setup-check\n')`. Both checks must succeed, with human prompts, before any real import. Stop if either fails. Remove dummy with `passage rm misc/setup-check` after successful checks. Store other approved personal `api/` or `misc/` values using `passage insert -m` from stdin, never an argument, printed plaintext, or decrypted temporary file.
